# Data Model

## Scope

This change does not add a database table or modify the persisted MERRICK intelligence model. It adds two small runtime contracts for window presentation and one versioned build-time evidence manifest for the marketing site and film.

## Runtime Entity: `WindowPresentationState`

Owned by the desktop shell and mirrored into the web UI.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `windowMode` | enum | yes | `normal`, `entering`, `fullscreen`, `exiting` |
| `readerMode` | enum | yes | `closed`, `organizer`, `newspaper-focus` |
| `selectedEditionId` | string or null | yes | Required only when `readerMode=newspaper-focus` |
| `editionScrollTop` | non-negative number | yes | Restored when leaving focus mode |
| `invokingControlId` | string or null | yes | Used to restore keyboard focus |
| `transitionId` | UUID string or null | yes | Correlates a web request with the native callback |
| `updatedAt` | ISO-8601 timestamp | yes | Monotonic per process |

### Invariants

1. `windowMode` and `readerMode` are orthogonal. Native fullscreen may contain either the normal organizer or the newspaper focus reader.
2. `newspaper-focus` is illegal without a selected edition.
3. A second native fullscreen request is ignored while `entering` or `exiting`.
4. Leaving `newspaper-focus` restores the organizer and its last edition scroll position.
5. Native fullscreen failure must return the mirrored state to `normal`; it must never leave the web UI in an optimistic fullscreen-only state.
6. The state is session-only. It is not written into memory, preferences, newspapers, or user documents.

## Bridge Message: `FullscreenRequest`

| Field | Type | Required | Rules |
|---|---|---:|---|
| `action` | literal | yes | `setWindowFullscreen` |
| `mode` | enum | yes | `enter`, `exit`, `toggle` |
| `requestId` | UUID string | yes | Generated by the web UI |

Unknown fields are ignored. Unknown actions, modes, and malformed identifiers are rejected at the bridge boundary.

## Native Event: `FullscreenStateEvent`

| Field | Type | Required | Rules |
|---|---|---:|---|
| `mode` | enum | yes | Same `windowMode` values as above |
| `requestId` | UUID string or null | yes | Null for a fullscreen transition initiated by macOS |
| `reason` | enum | yes | `web`, `native`, `failed` |
| `error` | string or null | yes | Sanitized user-displayable message; no paths or stack traces |

## Build-time Entity: `ShowcaseEvidenceManifest`

Stored as a versioned JSON artifact under `marketing-site/assets/evidence/`. It is a publication gate, not application data.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `schemaVersion` | integer | yes | Starts at `1` |
| `productRevision` | git revision string | yes | Revision from which captures were made |
| `generatedAt` | ISO-8601 timestamp | yes | UTC |
| `assets` | `MediaEvidenceAsset[]` | yes | Unique `id` and `path` |
| `proofs` | `CapabilityProof[]` | yes | One proof per published feature claim |

## Build-time Entity: `MediaEvidenceAsset`

| Field | Type | Required | Rules |
|---|---|---:|---|
| `id` | slug | yes | Stable across rerenders of the same evidence |
| `kind` | enum | yes | `image`, `video`, `audio`, `poster` |
| `path` | relative path | yes | Must remain within a public asset directory |
| `width` | positive integer or null | yes | Required for image, video, and poster |
| `height` | positive integer or null | yes | Required for image, video, and poster |
| `durationSeconds` | number or null | yes | Required for audio and video |
| `codec` | string or null | yes | Required for audio and video |
| `hasAudio` | boolean | yes | Video must declare this explicitly |
| `origin` | enum | yes | `direct-product-capture`, `product-audio`, `rendered-composite` |
| `captureScale` | number or null | yes | Direct visual captures must be at least `2` |
| `maxCssWidth` | positive integer or null | yes | Publication must not render beyond this width |
| `maxFilmWidth` | positive integer or null | yes | Film compositor must not exceed this width |
| `sha256` | 64-character hex string | yes | Detects stale or replaced evidence |
| `privacyReview` | enum | yes | `pending`, `approved`, `rejected` |
| `productState` | string | yes | Human-readable state that was captured |
| `alt` | string | yes | Describes the visible product state, not decorative framing |

### Asset invariants

1. A direct 7:5 product capture intended for a 980 CSS-pixel frame is at least 1960×1400.
2. `maxCssWidth <= width / 2` for direct captures published on high-density displays.
3. `maxFilmWidth <= width`; the compositor cannot enlarge product pixels.
4. Published product video has an approved poster, a visible first frame, and the declared audio state.
5. Generated mock UI cannot use `direct-product-capture` as its origin.
6. All published evidence is privacy-approved and pinned to a product revision.

## Build-time Entity: `CapabilityProof`

| Field | Type | Required | Rules |
|---|---|---:|---|
| `capabilityId` | enum | yes | `conversation`, `voice-identity`, `multi-page-research`, `mac-actions`, `documents-memory`, `operations`, `newspaper`, `plugins-skills` |
| `shippingStatus` | enum | yes | `shipping`, `preview`, `planned` |
| `claim` | string | yes | Exact public claim supported by the evidence |
| `surface` | string array | yes | At least one of `site`, `film`, `product` |
| `assetIds` | slug array | yes | References existing assets |
| `verifiedBy` | string | yes | Human or CI publication gate identity |
| `verifiedAt` | ISO-8601 timestamp | yes | Must not predate referenced assets |

### Truthfulness rule

Current direct product behavior can be marked `shipping`. Harness-generated/imported plugin execution remains `preview` or `planned` until its production execution path is released. The marketing site may show the current extension manager and durable plugin model, but cannot imply unrestricted generated-code execution is already shipping.

## Existing Models Reused

- Existing intelligence edition, story, citation, voiceprint, and extension records remain authoritative.
- The fullscreen reader consumes the already-rendered edition; it does not create a second newspaper format.
- Research source cards continue to use existing source URLs and metadata; the marketing proof records only the capture, not a copy of the research data.

## Migration and Retention

There is no database migration. Runtime presentation state expires with the app process. Evidence manifests and approved media are version-controlled release artifacts; superseded assets remain recoverable through git history but are removed from the current manifest.
